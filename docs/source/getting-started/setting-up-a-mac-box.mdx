---
title: Setting Up a Lager Box on a Mac
description: Turn the Apple silicon Mac in front of you into a Lager Box
---

Your Mac can be the Lager Box itself. Plug instruments into it and run `lager install`.
Then every `lager` command and `lager python` script works with them.

<Note>
The macOS Box is new. Most instruments that work on a Linux Box work on a Mac, but some
are not supported yet. See [What Is Not Supported Yet](#what-is-not-supported-yet)
before you rely on one.
</Note>

---

## How It Works

A Linux Box runs its Box software in a Docker container that reaches the USB instruments
directly. Docker on a Mac cannot pass USB devices into a container, so a Mac Box runs in
two parts:

- a **host agent**, a background service in your login session, that owns the USB
  instruments; and
- the **Box container**, which runs your scripts and the `lager` services. It has no
  device access and asks the agent for each instrument.

`lager install` sets up both. You do not run or configure the agent yourself.

---

## What You Need

- An **Apple silicon** Mac (M1 or later). Intel Macs are not supported.
- A current macOS. The port is developed and tested on macOS 14 and later.
- **Docker Desktop** or **OrbStack**. If Docker is installed but stopped, the installer
  starts it. If neither is installed, the installer offers to install OrbStack.
- **Homebrew** (recommended). The installer uses it for libusb, Rust, SEGGER J-Link,
  PicoScope 7, the ARM GDB, and OrbStack. Without Homebrew, those pieces are reported as
  "Not set up".
- **Python 3.10 or higher** and the Lager CLI: `pip3 install lager-cli`.
- An administrator account. The installer asks for your password once, to create
  `/etc/lager`.

---

## Step 1: Run the Installer in a Terminal

Open **Terminal** and run:

```bash
lager install
```

With no `--ip`, `lager install` installs on this Mac. Before it starts it:

- lists what Homebrew will install, and which installers ask for your password
  (SEGGER J-Link and PicoScope 7 do);
- asks to continue, and what name to save the Box under (default `local`).

It then:

- creates `/etc/lager` (your password is asked for once, by `sudo`);
- downloads the Box image (several GB the first time);
- sets up the host agent, LabJack support (U3/U6 and T4/T7/T8), J-Link and the ARM GDB;
- starts the agent and the Box container.

At the end, a **Set up:** line lists what is ready. A **Not set up:** line lists each
part it did not install, with the reason.

<Warning>
Run it in a terminal window, because the password prompt needs one. From a pipe, a
script or CI, the installer stops at once. It prints the commands that create
`/etc/lager` by hand:

```bash
sudo mkdir -p /etc/lager
sudo chown $USER /etc/lager
chmod 700 /etc/lager
```

After those, `lager install` needs no password.
</Warning>

Useful options:

| Option | Effect |
|---|---|
| `--skip-jlink` | Leave out SEGGER J-Link and the ARM GDB |
| `--skip-picoscope` | Leave out PicoScope and the scope daemon (needs Rust) |
| `--version VERSION` | Install that release, branch or commit instead of this CLI's version |
| `--yes` | Accept the defaults without asking |

`--version` takes a release (`v0.66.0`), a branch (`main`, `my-fix`) or a full 40-character
commit SHA.

A branch or commit has no Box image of its own. Its Box code runs on the published image of
the release that its `cli/__init__.py` names. Changes that it makes to the image itself are not
included, for example changes to the Dockerfile. To get new commits on a branch, run
`lager install --version <branch>` again.

The installer uses the `--version` that you name, also when you run the CLI from a checkout. To
install the checkout itself, do not use `--version`.

---

## Step 2: Verify

```bash
lager hello --box local
```

Use the name you chose in Step 1 instead of `local` if you changed it.

---

## Step 3: Add Nets

Nets are added the same way as on a Linux Box ([Setting Up
Instruments](/source/getting-started/setting-up-instruments)), with these differences.

- **Serial ports have Linux-style names.** Inside the Box, the Mac's `/dev/cu.*` ports
  are called `ttyUSB0`, `ttyUSB1`, ... (USB serial adapters) and `ttyACM0`, ... (USB CDC
  devices such as a J-Link VCOM), numbered in sorted order. A net saved with one of
  these names, a `serial://` address or a `/dev/serial/by-id/...` name works
  unchanged.
- **`/dev/serial/by-path` names are this Mac's own.** A by-path name records a USB
  socket on the machine that made it. A by-path name from a Linux Box does not work
  on a Mac. The Mac's names start with `/dev/serial/by-path/platform-macos-`. For a
  net that works on every Box, use the port's by-id name.
- **`lager instruments` opens no port on a Mac.** It reads the USB registry and shows
  the serial port of each adapter that it recognizes.
- **A LabJack T7 reports no serial number** on macOS, so its address ends in `::::INSTR`.
  Only one T7 per Mac can be told apart.

## Recovering

If an instrument stops answering:

1. Unplug it and plug it back in, then try the command again.
2. Restart the host agent:
   ```bash
   launchctl kickstart -k gui/$(id -u)/com.lagerdata.lager-host
   ```
3. Restart the Box container: `docker restart lager`.

<Note>
After you plug in a LabJack T7 again, an ADC read after a DAC change can show
the old value. To stop this, restart the host agent (step 2).
</Note>

Running `lager install` again repairs an install in place and keeps your nets.

---

## Updating

```bash
lager update --box local
```

This installs the Box again at this CLI's version. It leaves out the parts that your last
`lager install` left out with `--skip-jlink` or `--skip-picoscope`. The installer
downloads the new Box image before it stops the running Box. If the download fails, the
running Box stays as it was.

---

## Uninstalling

```bash
lager uninstall
```

This removes the agent, the container and the agent's files. `/etc/lager` (your saved
nets) is kept. With `--purge-config`, the installer copies `/etc/lager` to your home
directory, then empties it. The directory itself stays.

Docker must be running. If Docker is installed but stopped, the uninstall removes
nothing. Start Docker, then run `lager uninstall` again.

---

## Installing on Another Mac

You can install a Box on a Mac that you reach over SSH:

```bash
lager install --ip <mac-address> --user <mac-user>
```

The CLI copies the installer to that Mac and runs it there. Run the command in a
terminal, because that Mac asks for its password once, to create `/etc/lager`.
`lager update` and `lager uninstall` with the same address work on that Mac.

<Warning>
A Box on another Mac listens on every network interface, so other machines can reach
it. A Linux Box has a firewall in front of these ports. A Mac Box does not. Install a
Box on another Mac only on a network that you trust.
</Warning>

## What Is Not Supported Yet

These work on a Linux Box but not yet on a Mac Box:

- OpenOCD debug probes (J-Link works);
- Rigol oscilloscopes and logic analyzers (PicoScope works);
- webcams and HDMI capture;
- Bluetooth (BLE) and BluFi;
- `lager diagnose`, DFU, and `lager update --check` for a local Box.

Not planned: WiFi control, and scripts that use raw USB, pyftdi or bleak directly.
Those fail with a clear message.
