---
title: USB Hub Ports
description: Power-cycle a programmable USB hub port
---

Cut and restore power to one port of a programmable USB hub. A test uses this to force
a DUT to re-enumerate, or to simulate a cable pull.

## Handle

```rust
use lager::LagerBox;

let lager = LagerBox::from_env()?;
let port = lager.usb("usb1");
```

## Methods

| Method | Description |
|--------|-------------|
| `name()` | The net name this handle addresses |
| `enable()` | Power the port on |
| `disable()` | Power the port off |
| `toggle()` | Invert the port and report the new state |
| `state()` | Read whether the port is currently powered |
| `cycle()`, `cycle_with_off_time()` | Power off, wait, power on, and report whether the device came back |
| `cycle_report()` | Like `cycle()`, and also say why a device did not come back |
| `recover()` | Power a port back on after an interrupted command |

## Method Reference

### `enable() -> Result<()>` and `disable() -> Result<()>`

Power the port on or off.

```rust
port.disable()?;
std::thread::sleep(std::time::Duration::from_secs(1));
port.enable()?;
```

### `toggle() -> Result<bool>`

Invert the port's power state.

**Returns:** `true` if the port is now **enabled**, `false` if now disabled — the
state after the toggle, not before.

### `state() -> Result<bool>`

Read whether the port is powered.

```rust
assert!(port.state()?, "port should be up");
```

**Returns:** `true` when enabled.

<Note>
  `state()` needs box software 0.29.0 or newer. Older boxes reject the action, and
  the crate turns that specific rejection into `Error::UnsupportedByBox` with the
  message
  `the 'state' action on /usb/command requires box software >= 0.29.0; update the box or use toggle/enable/disable`.
</Note>

### `cycle() -> Result<Option<bool>>`

Power the port off, wait, and power it on again. The box watches for the device to
re-enumerate. It requires box software 0.39.0 or later.

```rust
match port.cycle()? {
    Some(true) => println!("the DUT came back"),
    Some(false) => panic!("the DUT did not re-enumerate"),
    None => println!("the port was empty, or the hub cannot watch for the device"),
}
```

The port is powered at the end on every path, including failures. The default off
time is 1 s. `cycle_with_off_time(secs)` takes another value from 0.5 to 10 s. When in
doubt, choose a longer time: a short one lets the DUT warm-start without a real reset.

### `cycle_report(off_time_secs: Option<f64>) -> Result<UsbCycleReport>`

Like `cycle()`, and the report also carries the box's `outcome` (box 0.49.0 or later).
A `UsbCycleReport` has three fields: `reconnected`, the same value that `cycle()` returns;
`outcome`; and the box's `message`.
The outcome tells an empty port apart from a port the box did not watch:

| `UsbCycleOutcome` | Meaning |
|---|---|
| `Reconnected` | The device re-enumerated after power returned |
| `NotReconnected` | The device did not come back before the box's timeout |
| `NoDevice` | Nothing on the port was on the bus when the cycle started |
| `TopologyUnreadable` | The box did not read its USB topology |

### `recover() -> Result<()>`

Power the port on again after a command stopped partway through. On a Plugable dock,
this powers every port of that dock.

## Examples

### Force a DUT to re-enumerate and wait for it to come back

```rust
use lager::{LagerBox, UsbDeviceFilter};
use std::time::{Duration, Instant};

let lager = LagerBox::from_env()?;
let port = lager.usb("usb3");

port.disable()?;
std::thread::sleep(Duration::from_millis(500));
port.enable()?;

// Poll the bus until the DUT reappears. usb_devices() is cheap and takes no
// exclusive access, so this loop is safe.
let filter = UsbDeviceFilter { vid: Some("0483".into()), ..Default::default() };
let deadline = Instant::now() + Duration::from_secs(10);
loop {
    if !lager.usb_devices_matching(&filter)?.is_empty() {
        break;
    }
    assert!(Instant::now() < deadline, "DUT did not re-enumerate");
    std::thread::sleep(Duration::from_millis(200));
}
```

<Warning>
  On a Plugable dock, a device on a powered-off port stays listed on the bus until
  power returns. The loop above can then match the old entry at once, before the DUT
  re-enumerates. Use `cycle()` instead, which waits for the hub to report the
  reconnect.
</Warning>

## Supported Hardware

| Instrument | Ports |
|---|---|
| Acroname USBHub3+ | 8 or 4, depending on model |
| YKUSH hub | Per model |
| Plugable USB hub | Addressed by topology rather than serial |

## Notes

- One net is one port. Cycling `usb1` leaves the hub's other ports alone.
- The port's `devnum` on the bus changes across a re-enumeration. Match a device by
  serial or vid/pid, never by `devnum`, when checking that it came back.
- Powering a port down can remove a device that the box uses for another net. A
  debug probe or serial adapter behind that port will disappear mid-test.
