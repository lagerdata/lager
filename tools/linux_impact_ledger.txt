# Linux impact ledger for the macOS port.
#
# Rule: the working Linux Box must not regress. Every file that already
# exists on main under box/ or cli/ and is changed, renamed, or deleted by
# this work must be listed here BEFORE the change is committed.
# tools/check_linux_impact.py enforces it.
#
# New files need no entry: a Linux Box does not run them unless an existing
# file is changed to call them, and that change is what gets listed.
#
# One entry per line, four fields separated by " | ":
#
#   path | effect on a Linux Box | risk (low/medium/high) | how it was verified
#
# "path" is repo-relative and matched exactly. The last field must say plainly
# whether the change was run on real Linux hardware. Automated hardware runs
# are disabled, so "unit suites only; not run on Linux hardware" is the honest
# default until someone runs it on a bench.
#

cli/commands/utility/install.py | `lager install` with neither --box nor --ip used to print "Either --box or --ip is required" and exit 1. With --box or --ip the code path is unchanged, except that a CLI running on macOS sends a loopback address to the same local install; that check is always false on Linux and Windows. With --box or --ip and a target that is not this Mac, one command is added after the SSH check succeeds: `ssh -o BatchMode=yes <box> uname -s` (20 s limit). Only the exact answer "Darwin" leaves the Linux path, for the macOS installer; any other answer, an error, a timeout or no answer continues to the unchanged gateway check and deploy. A Linux install therefore makes one more SSH connection than before. Later change to the no-target case on Linux: instead of the "not yet supported" exit, a bare `lager install` checks that 127.0.0.1 port 22 answers and then continues into the same SSH install with ip=127.0.0.1 and the user running the CLI (or --user). With --box or --ip nothing changes. The `uname -s` probe carries `-o ConnectTimeout=10`, reads no stdin, and treats every failure or unexpected answer as "not a Mac". Also: lager install --ip asks the box `sudo -n true` (BatchMode) when stdin is not a terminal, and stops before deploying if a password is needed. From a terminal nothing changes | medium | CLI unit suite (test_install_terminal_precheck.py); Linux Box run before release
